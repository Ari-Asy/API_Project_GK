โครงสร้างของ JWT
หน้าตาของ JWT จะเป็นสตริงข้อความยาวๆ ที่ถูกคั่นด้วยจุด (.) แบ่งออกเป็น 3 ส่วนหลักๆ คือ
1:Header: ระบุข้อมูลประเภทของ Token และอัลกอริทึมที่ใช้ในการเข้ารหัสลายเซ็น (เช่น HMAC SHA256)
2:Payload: ส่วนที่เก็บข้อมูลสำคัญ (Claim) เช่น ข้อมูลระบุตัวตนของผู้ใช้ (User ID), สิทธิ์การเข้าใช้งาน (Role), และวันหมดอายุ
3:Signature: ส่วนที่นำ Header และ Payload มาเข้ารหัสรวมกับรหัสลับฝั่งเซิร์ฟเวอร์ (Secret Key) เพื่อใช้ตรวจสอบว่าข้อมูลถูกแก้ไขหรือปลอมแปลงหรือไม่

HTTP method
- คือประเภทของ request ที่ client ส่งมาให้ server
// GET = ขอดูข้อมูล
// POST = สร้างข้อมูลใหม่ หรือส่งข้อมูลไปให้ server ประมวลผล
// PUT = แก้ไขข้อมูลทั้งหมด อย่างการแก้ไขข้อมูลของ ID1 ทั้ง field
// PATCH = แก้ไขข้อมูลบางส่วน ไม่ได้แก้ทุก field
// DELETE = ลบข้อมูลทิ้ง
// HEAD = เหมือน GET แต่ server ส่งกลับมาเฉพาะ header ไม่ส่ง body ใช้เช็คว่ามีข้อมูลไหม URL ใช้ได้ไหม
// OPTIONS = ใช้ดู server ว่า endpoint นี้รองรับ method อะไรบ้าง
ถ้าเทียบกกับ CRUD
- Create -> POST
- Read -> GET
- Update -> PUT/PATCH
- Delete -> DELETE
